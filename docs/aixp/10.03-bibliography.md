# Appendix C - Bibliography and Lineage

**Extreme Programming (primary sources)**
- Kent Beck, [*Extreme Programming Explained: Embrace Change*](https://www.oreilly.com/library/view/extreme-programming-explained/0321278658/) (2nd ed., 2004) - the canonical source for the 12 practices
- Kent Beck & Cynthia Andres, [*Planning Extreme Programming*](https://www.oreilly.com/library/view/planning-extreme-programming/0201710919/) (2000)
- Ron Jeffries, Ann Anderson, Chet Hendrickson, [*Extreme Programming Installed*](https://www.oreilly.com/library/view/extreme-programming-installed/0201708426/) (2000)

**Agile / Kanban / Lean**
- [*Manifesto for Agile Software Development*](https://agilemanifesto.org/) - the four value-pairs, useful as a structural contrast point for whatever manifesto format this project lands on
- Mary Poppendieck & Tom Poppendieck, [*Lean Software Development: An Agile Toolkit*](https://www.poppendieck.com/) (2003) - source of the "eliminate waste" framing referenced under Simple Design/YAGNI
- David J. Anderson, [*Kanban: Successful Evolutionary Change for Your Technology Business*](https://djaa.com/kanban-successful-evolutionary-change-for-your-technology-business/) (2010) - WIP limits, pull systems

**Architecture / Design Discipline**
- Neal Ford, Rebecca Parsons, Patrick Kua, [*Building Evolutionary Architectures*](https://evolutionaryarchitecture.com/) (2017) - source of "fitness functions," relevant to bounding refactoring/scope creep and possibly Metaphor's replacement
- Eric Evans, [*Domain-Driven Design: Tackling Complexity in the Heart of Software*](https://www.domainlanguage.com/ddd/) (2003) - relevant background for Domain Gap Surfacing and ADR-level spec work
- Michael Nygard's ADR format (original blog post: ["Documenting Architecture Decisions"](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions), 2011; see also [adr.github.io](https://adr.github.io/)) - likely the direct ancestor of the spec-first ADR practice

**DevOps / SRE (relevant to Merge/Integration Authority)**
- Gene Kim, Kevin Behr, George Spafford, [*The Phoenix Project*](https://itrevolution.com/product/the-phoenix-project/) (2013) - narrative introduction to DevOps flow concepts
- Google, [*Site Reliability Engineering*](https://sre.google/sre-book/table-of-contents/) (2016, free online: [sre.google/books](https://sre.google/books/)) - error budgets, postmortems, relevant to merge-bottleneck/candidate-build thinking
- Jez Humble & David Farley, [*Continuous Delivery*](https://continuousdelivery.com/) (2010) - the deeper technical background behind CI/CD risk-tiering

**Adjacent "AI-Native SDLC" Literature (for direct comparison - see Chapter 8)**
- Anthropic Applied AI team, ["The AI-Native SDLC playbook"](https://academy.claude.com/courses/ai-native-sdlc-playbook/introduction) ([Claude Blog](https://claude.com/blog), August 21, 2026) - the primary comparison point for Chapter 8; org-scale, artifact-driven (intent.md/spec.md/plan.md), no XP lineage
- AWS (Raja SP), ["AI-Driven Development Lifecycle (AI-DLC)"](https://aws.amazon.com/blogs/developer-tools/open-sourcing-adaptive-workflows-for-ai-driven-development-life-cycle-ai-dlc/) (2025) - a competing org-scale framing, worth reading alongside the Anthropic playbook for contrast

**AI-Assisted Development**
- Kent Beck, [*Software Design: Tidy First?*](https://tidyfirst.substack.com/):
  - ["Trust Factory"](https://tidyfirst.substack.com/p/trust-factory) (June 2026) - reframes XP practices as trust-manufacturing mechanisms, examines the code-vs-trust deficit in AI development, and references emerging "XPAI"
  - ["Augmented Coding: Beyond the Vibes"](https://tidyfirst.substack.com/p/augmented-coding-beyond-the-vibes) (June 2025) - foundational distinction between "vibe coding" and disciplined "augmented coding" bounded by TDD and structural hygiene
  - ["The Genie Eats The Seed Corn"](https://tidyfirst.substack.com/p/augmented-coding-and-design) (published as "Augmented Coding & Design", May 2025) - how AI coding assistants lack incentives to refactor, eating into future maintainability for short-term feature output
- Anthropic's engineering blog and documentation on [Claude Code](https://docs.anthropic.com/en/docs/agents-and-tools/claude-code/overview) ([claude.com/docs](https://docs.anthropic.com/)) - primary source for tooling architecture, workflows, and capabilities
- [GitHub's engineering blog on Copilot usage patterns](https://github.blog/news-insights/research/) - useful comparative data on AI-pairing at scale in human teams, different context (large orgs, not solo/small-team) but relevant contrast
- [arXiv Software Engineering (cs.SE)](https://arxiv.org/list/cs.SE/recent) - repository for preprints and empirical research on AI pair programming, LLM code review, and agentic software development

**Adjacent/Contrasting Methodologies (mentioned but not adopted)**
- Harlan Mills et al. on [Cleanroom Software Engineering](https://en.wikipedia.org/wiki/Cleanroom_software_engineering) (IBM technical reports, 1980s; see also [Mills et al., "Cleanroom Software Engineering," IEEE Software, 1987](https://ieeexplore.ieee.org/document/1702029)) - mostly of historical interest but relevant to the "formal spec, AI implements faithfully" thread
- Dan North, ["Introducing BDD"](https://dannorth.net/introducing-bdd/) (2006, original article) - Given/When/Then framing, relevant to Spec-First Prompting's executable-adjacent variants

**Versioning / Release Discipline**
- Tom Preston-Werner, [*Semantic Versioning 2.0.0*](https://semver.org/) - the canonical SemVer spec
- [*Conventional Commits*](https://www.conventionalcommits.org/) - specification for adding human- and machine-readable meaning to commit messages, referenced under Coding Standards
- [CalVer](https://calver.org/) - informal reference for calendar-based versioning schemes and when teams choose it over SemVer
